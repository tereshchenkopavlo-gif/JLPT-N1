# Незалежне мовне приймання

Канонічна гілка черги — work/independent-queue. Читати її поточну вершину перед новим пакетом або результатом. Гілки з навчальними змінами можуть посилатися на цю чергу без перенесення змін рушія.

Рецензент відкриває [QUEUE.md](QUEUE.md), вибирає найстарший pending_review і читає лише його JSON-пакет та інструкції всередині. Авторські розгляди й попередні рецензії відкриваються після першого висновку. Результат повертається одним JSON за шаблоном пакета. Посилання з черги дозволяє працювати без пересилання вихідного файлу.

## Файли й незмінність

- packages/ містить незмінні передані пакети. Старі кореневі JSON залишені для сумісності вже виданих посилань; їхні байти збігаються з канонічними копіями.
- reviews/ містить по одному файлу кожної рецензії. Історичний результат IR01 перенесено зі results/ без зміни байтів. Джерело пакета й результат зв'язані через package_id та sources_sha256.
- queue.json є машиночитним реєстром. QUEUE.md показує ті самі стани, SHA джерел, повні SHA-256 файлів і посилання.
- acceptance-register.json зберігає точні поля й виключення фактично отриманих переглядів.

Новий пакет отримує унікальний ID та SHA джерел. Пакет і рядок черги публікуються одним Git-комітом. Його commit SHA є в історії файла; SHA вихідних матеріалів зафіксовано окремо в пакеті та черзі. Перед передачею звірити віддалені blob SHA з локальними. Після передачі файл не перезаписується. Виправлення отримують новий ID або ревізію з predecessor та точним переліком повторно перевірюваних полів.

Перед новим пакетом перевірити queue.json і контрольні суми матеріалів у pending_review/in_review. Тотожний case_id з тим самим вмістом уже в активній перевірці не ставити повторно. Незмінені супровідні тексти можна включити до ревізії як контекст змінених запитань, вказавши попередній пакет. Уже отримані докази перевикористовувати тільки для тих самих байтів і полів.

## Стани

| Статус | Значення |
|---|---|
| pending_review | Опублікований пакет очікує рецензента |
| in_review | Рецензент явно підтвердив початок |
| review_received | Рецензію зареєстровано після технічної перевірки |
| reviewed_with_issues | Отримано й перевірено відповідність висновку з зауваженнями |
| reviewed_pass | Отримано висновок без відкритих зауважень у заявленому scope |
| corrections_pending | Авторський розгляд підтвердив правки або потрібен їх повторний перегляд |
| closed | Scope опрацьовано, усі рішення й залишкові обмеження зафіксовані |

Історію переходів зберігати. reviewed_pass та closed не надають кредиту неперевіреним полям. closed може бути адміністративним завершенням пакета з відхиленими пропозиціями, але тоді точний результат і обмеження мають бути вказані. IR01 перебуває в corrections_pending до повторної перевірки виправлень у IR02.

## Повернення результатів

Звірити package_id, sources_sha256, перелік cases, відсутність дублікатів та всі заявлені checked/unchecked поля. Зберегти рецензію без зміни змісту, записати її checksum, шлях до пакета та статус одним комітом. Імпортер completion/import-independent-review.py виконує початкову перевірку й збереження; Синхронізація позначає отримання, авторський розгляд визначає подальший стан. Повторний ідентичний результат перевикористовується. Навчальні дані й кредит не змінюються автоматично.

Для перевірки черги виконати python3 completion/independent/validate-queue.py. Щоб перевірити матеріал перед новим пакетом, додати --candidate PATH. Валідатор перевіряє відповідність checksum, sources_sha256, джерел і рецензій та тотожні активні матеріали.

Основний аудит і C12 продовжуються під час очікування рецензій. Погодження користувачем кожної партії не потрібне. Повний порядок відповідальності — [../INDEPENDENT_REVIEW.md](../INDEPENDENT_REVIEW.md).

## Отримання, повторна перевірка та облік

Публікація нового JSON у `reviews/` запускає GitHub Actions на гілці черги. Щоб зареєструвати файли в тому самому коміті, виконайте `python3 completion/independent/sync-reviews.py`. Синхронізація перевіряє контрольні суми наявних доказів, структуру нових результатів, покриття й унікальність сеансу рецензента в межах пакета. Новий стан `review_received` означає технічне отримання і очікування авторського розгляду. Поточне рішення автора та попередні переходи зберігаються. Помилка перевірки блокує запис реєстру. Повторний запуск ідемпотентний.

Перед реєстрацією нового пакета запустіть `python3 completion/independent/preflight.py PATH`. Перевірте сигнали про підозрілі альтернативи до передачі пакета. Рецензент перевіряє природність японської, точність перекладів, обґрунтованість ключів та правдоподібність кожної альтернативи. Орієнтир пілота — 10–20 текстів за спільну партію. Підгрупи можуть мати окремі ID, джерела й рецензії, щоб завершені частини можна було розглядати одразу. Обсяг словникової партії визначайте за кількістю контекстів і мовних рішень на картку.

Для ревізії запустіть `python3 completion/independent/recheck-plan.py PATH`. План зіставляє поля та залежності за контрольними сумами і шукає підтвердження в реєстрі та незмінній рецензії. Питання перевіряється разом з ключем, альтернативами, поясненням і цитатою. Зміна тексту або перекладу повертає залежні питання й примітки до перегляду. Якщо в попередньому доказі є виключення, зауваження до поля чи бракує точного покриття, поле знову йде на перевірку. План не записує кредит. Першому незалежному рецензенту давайте повний контекст і перелік потрібних полів без попередніх висновків.

Після кожного отримання розглядайте підтверджені виправлення невеликими інтеграційними партіями. Застосовуйте їх до актуального кандидата після звірки дрейфу й залежних тестів, зберігайте докази та ставте в чергу лише необхідний повторний перегляд. C12 та нові матеріали можуть просуватися в окремій гілці під час розгляду. Після мовної перевірки, авторського рішення й інтеграції зафіксуйте фактично закриті ID у `closed_case_ids` відповідного пакета зі станом `closed` та посиланням на докази в історії. Для адміністративного закриття залиште список порожнім.

`python3 completion/independent/audit-metrics.py` показує унікальні опубліковані в пакетах випадки, випадки з перевіреними полями, зафіксованими виправленнями й явним закриттям, залишок за станами та час до першої рецензії й закриття. Ревізії одного case_id враховано один раз. Історичні дати мають точність до календарного дня. Головний показник для порівняння розмірів партій — приріст явно закритих випадків за однаковий проміжок, із тим самим стандартом перевірки.
