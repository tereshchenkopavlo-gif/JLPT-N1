# Практичне приймання на Android та Windows

5 листопада 2026, Asia/Tokyo. **План підготовлено; фізичні випробування не проведено. C16 залишається відкритим.** Автоматизований Chromium, вузьке вікно, скріншот у Linux і структурний тест не зараховуються як результат на цих пристроях.

Кандидат для цього проходу: [повний v141](../JLPT_N1_ukrainian_reading_v141.html), SHA-256 `08e016a95f1786f243c29f54289edf5dd65aac4c43c9ff863b25c9f0422f75a3`. Для перевірки перенесення — [v140](../JLPT_N1_ukrainian_reading_v140.html), SHA-256 `810af1aecf5a71b2fbd39b687e3ec310763317cb3f04821107cdeb983c31f537`. Якщо зміниться файл, результат нового кандидата має окремий журнал; старий результат не переписується.

## Пристрої та підготовка

| Середовище | Що записати перед початком |
|---|---|
| Фізичний Arrows F-51F користувача | Точну версію Android, браузер і його версію, спосіб відкриття файла, адресу/тип `file://` або `content://`, клавіатуру, орієнтацію, масштаб браузера й системний розмір шрифту. Не вгадувати ці дані за моделлю. |
| Фізичний ПК користувача з Windows | Версію/збірку Windows, браузер і його версію, масштаб екрана, масштаб браузера, шлях відкриття HTML, доступні японські шрифти/голоси. Спочатку тестувати браузер, яким користувач реально користується. |

Перед змінами оцінок експортувати справжній прогрес у 設定, переконатися, що JSON-файл завантажено й він відкривається, та зберегти незмінну резервну копію. Не починати експерименти, якщо резервне копіювання не працює. Не натискати скидання прогресу. Для Windows бажаний окремий тестовий профіль браузера; інша назва HTML на Android **не гарантує** ізольованого сховища. Спочатку перевірити, який прогрес фактично видно.

Робочий контрольний набір ID: 語彙 22 横顔, 3005 著しい, 3112 顕著; 文法 9 〜ばこそ, 57/85 〜にたえない. Для перевірки однакових написань додати 語彙 1634/3164/3363 相当. Це не заміна мовного аудиту всіх карток. До й після тесту зафіксувати вибрані оцінки, цілі, налаштування й склад порівняння; для всього сховища доказом є контрольне відновлення резервної копії.

## Як оформити приймання

Порожній шаблон — [physical-device-results-template.csv](physical-device-results-template.csv). Для реального випробування створити датовану копію шаблона, не переписувати його як історичний результат. Початково всі 32 сценарії мають `not_run`: 16 для Android і 16 для Windows. Поля: дата, фактична модель/ОС/браузер, спосіб відкриття, SHA кандидата, ID сценарію, результат, очікуване/фактичне, доказ, ID дефекту. Скріншот без моделі/версії/сценарію не закриває весь C16. Докази з особистими даними не публікувати; достатні обрізаний знімок, точні ID та опис.

Перший короткий прохід P01/P02/P04/P07/P10/P11/P16 виявляє основні блокери; після нього завершити решту матриці. Загублені оцінки, невідновлюваний backup, неправильний ключ, непрацездатне відкриття чи недоступна основна кнопка блокують приймання кандидата. Косметичне зауваження оформити окремо за фактичним впливом. Відсутність озвучення без локального голосу й C15 описати за їхніми межами, не оголошувати автоматично ні успіхом, ні універсальним дефектом застосунку.

C16 закривається лише після фактичних записів із двох фізичних середовищ та розбору всіх суттєвих відмов. Поки журнал порожній, статус готовності залишається «практичне приймання не проведено».
